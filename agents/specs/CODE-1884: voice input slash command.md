# CODE-1884: Voice input V0 — `/voice` slash command

*Spec: Voice input V0 — start recording from `/voice`, show a mode indicator, and stop/transcribe with `Esc`*

== PRODUCT ==
*Summary:* Add a no-argument `/voice` slash command to the normal Warp input. Selecting or submitting it immediately starts the existing voice recorder. While the session is active, the input shows a voice-mode affordance in the same bottom-left/prefix area used by the shell-mode hint; voice owns that area over the shell `!` hint. Pressing `Esc` ends a slash-command-started recording and transcribes it (rather than aborting it), with a visible `Transcribing...` state until the existing transcription result is applied.

*Key design choices:* Reuse the existing recorder/transcriber and `VoiceInputState` lifecycle; add an explicit slash-command session origin so `Esc` can stop versus abort without changing hold-to-talk/button semantics; render a compact voice indicator in the editor's left-notch/prefix path and retain the existing empty-buffer placeholder text; hide `/voice` when the compiled voice entitlement, workspace policy, or user AI voice setting is unavailable.

*Behavior* (numbered, testable invariants):
1. In a supported GUI terminal/agent input, `/voice` is listed as a no-argument slash command when `UserWorkspaces::is_voice_enabled()` and `AISettings::is_voice_input_enabled()` are true. Selecting it from the menu or submitting exactly `/voice` starts recording immediately; it does not insert `/voice` into the buffer or submit an AI prompt.
2. `/voice` accepts no argument. Exact `/voice` and `/voice` followed only by whitespace execute; `/voice anything` is not treated as a complete command.
3. The command uses the existing `VoiceInput::start_listening`/`VoiceSession` and editor voice lifecycle. It must not create a second recorder, transcriber, or parallel voice state machine.
4. While slash-originated recording is `Listening`, the input shows a voice indicator in the same bottom-left/left-notch area as the existing shell-mode hint. The indicator includes a microphone affordance and the status text `Listening...` (or the existing localized equivalent if the UI has a localization abstraction). The existing voice cursor affordance may remain.
5. While slash-originated audio is being transcribed, the same indicator remains visible with a progress affordance and the exact status text `Transcribing...`. The existing empty-buffer placeholder is also `Transcribing...`; when the buffer is non-empty, the left-notch indicator remains the source of truth.
6. While voice is `Listening` or `Transcribing`, the voice indicator takes precedence over the shell `!` indicator: both must never be rendered at once. Cloud handoff `&` behavior is unchanged; `/voice` is unavailable in cloud-agent composition, so no new cloud/voice precedence is introduced.
7. Pressing `Esc` while a slash-originated session is `Listening` calls the successful-stop path (`stop_voice_input(false)`), produces an audio result, and transitions to `Transcribing`. It must not call `abort_listening`, emit an aborted/cancelled voice result, or discard the recording. The generic editor escape event must not prevent the stop/transcribe transition.
8. Pressing `Esc` while a slash-originated session is already `Transcribing` does not cancel the in-flight transcription. The input remains in the transcribing state until the existing future completes.
9. When transcription succeeds, the existing `apply_transcribed_voice_input` path inserts the returned text through `user_insert`, clears the voice indicator, restores the normal zero-state hint, and restores the interaction state that was active before voice started.
10. When transcription fails, the existing quota-limit and generic voice error toasts are reused, the indicator is cleared, and the editor returns to its pre-voice interaction state. Microphone denial continues to use the existing microphone-access toast.
11. Existing hold-to-talk/key and microphone-button sessions retain their current behavior: their stop/cancel path remains `abort_listening` on the key-release/cancel escape route, and a normal button/key toggle still uses the existing successful stop behavior where already defined. The slash-origin distinction must not change their telemetry, toasts, or insertion behavior.
12. If voice is disabled by the compile-time feature, workspace/team policy, AI availability, or `voice_input_enabled_internal`, `/voice` is omitted from the GUI command results. The GUI data source recomputes this when the relevant AI setting or workspace/team state changes. A stale/racing dispatch must re-check the same gates and must not start recording.
13. `/voice` is not added to `TuiSlashCommand` and is not added to the CLI-agent rich-input allowlist (`/prompts` and `/skills` remain unchanged). The command is not offered in cloud-agent composition.

*Design alternatives*:
- *Use the existing toggle action for `/voice`.* Rejected: when already listening, toggle semantics stop rather than unambiguously start, and the current editor `Esc` path aborts. A dedicated slash-command dispatch calls the same internal start/session machinery with an explicit origin and makes the contract testable.
- *Treat every `Esc` as successful stop.* Rejected: existing hold-to-talk and button cancellation rely on abort behavior and must not regress. The selected design stores a `VoiceInputSessionOrigin` (slash command versus existing key/button source) for the active editor session; only the slash origin changes `Esc` from cancel to successful stop.
- *Use only the existing cursor icon and empty-buffer placeholder.* Rejected: placeholders disappear when the user has typed text and do not satisfy a persistent bottom-left mode indicator. The selected design adds voice content to the existing left-notch decorator and keeps the placeholder as a complementary empty-buffer affordance.
- *Leave `/voice` visible and show a disabled toast.* Rejected for V0: command availability already supports runtime filtering, and hiding an unavailable command avoids a command that can never start. A race-safe execution gate still prevents recording if entitlements change after menu population.
- *Add voice to the TUI/CLI-agent command surfaces.* Rejected: those surfaces have separate execution/input lifecycles and no requested transcription insertion path. V0 is normal GUI input only.

*Proposed changes:*
1. Add a static `VOICE` command (`name: "/voice"`, descriptive voice icon, `Availability::AI_ENABLED | Availability::NOT_CLOUD_AGENT`, `argument: None`) and include it in `all_commands`. Keep it out of `TuiSlashCommand`; TUI filtering will therefore exclude it.
2. Add a GUI command gate for `VOICE` requiring both `UserWorkspaces::is_voice_enabled()` and `AISettings::is_voice_input_enabled()`. Recompute on `VoiceInputEnabled` and existing team/workspace events. Preserve the CLI-agent allowlist behavior and cloud-agent exclusion.
3. Add an explicit `Input`/`EditorView` slash-start action that checks the gates, enters the existing AI input mode as appropriate, starts the existing recorder once, focuses the editor, and records the active session origin as `SlashCommand`. Do not route through a toggle that can stop an already-active session.
4. Extend the editor voice session bookkeeping with an origin that is set only after a successful slash start and is cleared on aborted, stopped, failed, or completed sessions. Update the `Esc` path so slash-originated `Listening` calls `stop_voice_input(false)` before generic escape propagation; non-slash sources retain `stop_voice_input(true)` where they do today. `Transcribing` remains non-cancellable from `Esc`.
5. Add a voice left-notch renderer alongside `maybe_render_ai_input_indicators`: `Listening` renders microphone + `Listening...`; `Transcribing` renders progress/dots + `Transcribing...`; `Stopped` renders nothing. Make this renderer run before shell-mode composition and suppress the shell `!` when voice is active. Ensure state updates invalidate the editor decorator, including when the buffer is non-empty.
6. Keep `VoiceStateUpdated` placeholder handling, `apply_transcribed_voice_input`, quota/microphone/error toasts, and interaction-state restoration on the existing paths. The new behavior is an origin/dispatch/indicator change, not a new transcription backend.
7. Add focused tests in the existing slash-command model/input test modules and voice/editor tests; use a deterministic voice-session/transcriber seam or mocked session result for tests so no physical microphone or network service is required.

*Open questions resolved:* The ticket's “triggers voice input” means immediate recording on command execution, not a primed mode. The indicator is the existing editor left-notch/prefix affordance, with explicit `Listening...` and `Transcribing...` labels; the empty-buffer placeholder remains for compatibility. Unavailable voice is hidden from the GUI command menu, while a race-safe dispatch re-checks gates. V0 covers normal GUI input only; TUI, CLI-agent rich input, and cloud-agent composition are out of scope. Cloud handoff keeps its existing higher-level indicator semantics because `/voice` is not available there.

*Risks / blast radius:* Voice runs asynchronously and changes editor interaction locking, so stale origin state could cause an `Esc` to stop a later session or leave the editor locked. Mitigate by setting origin only after successful start, clearing it on every terminal state, and asserting transitions in tests. Left-notch composition can regress shell/AI visual hints; use explicit precedence tests and preserve cloud handoff behavior. Runtime entitlement changes can race menu dispatch; gate both availability and start. Microphone permissions, quota, and transcription failures must continue using existing toasts.
